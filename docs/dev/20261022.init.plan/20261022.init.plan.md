# storeluna-gogo 项目初始化与架构规划 (2026-10-22)

## 1. 项目定位与背景
- **目标**：使用纯 Go 重构 `storeluna` 插件市场索引服务，替代 84 机器上仅为提供市场索引而常驻的 `ovo-bot`（Node.js/Koishi 运行时）。
- **收益**：内存由 300MB+ 降至约 15MB；消除并发请求导致的死锁假死；毫秒级启动与单二进制无依赖分发。

## 2. 核心架构与双端口安全模型
服务采用“公共服务”与“管理控制台”物理端口隔离设计，必须配置不同端口：

| 模块 | 默认端口 | 监听范围 | 路由与用途 |
| :--- | :--- | :--- | :--- |
| **Server** | `55150` | `0.0.0.0/0` (全网) | `/storeluna/index.json`, `/market`, `/healthz` (供 FRP 穿透与客户端拉取) |
| **WebUI** | `65150` | 局域网白名单 | `/`, `/api/config`, `/api/sync` (管理后台、配置热更、手动同步) |

- **CIDR 白名单防护**：WebUI 内置 IP 拦截中间件，仅允许 `127.0.0.1`、`::1` 及 `192.168.31.0/24` 等家庭局域网访问，非白名单请求直接返回 `403 Forbidden`。
- **端口互斥防呆**：启动时校验 `server.port != webui.port`，相同则阻止启动。

## 3. 工作模式与版本解析策略
- **工作模式 (双模)**：
  - `mirror` (默认推荐)：定期 (如 30m) 极速从官方 `registry.koishi.chat` (或 GitHub 原始仓库) 拉取完整底座，1 秒完成，零网络风暴。
  - `crawler` (备选自爬)：直接并发扫描 npmmirror `koishi-plugin-`，带 Worker Pool (如 5~10 并发) 与超时熔断，彻底规避 Node 版死锁。
- **版本规范**：严格遵循官方规范，以 NPM 的 `dist-tags.latest` 为准，保证与 Koishi 控制台及各大 WebUI 100% 兼容。

## 4. WebUI 与界面安全
- **单文件嵌入**：使用 `go:embed` 将前端静态资源编译进可执行文件，零外部静态文件依赖。
- **双向实时绑定**：UI 界面直接映射并热重载 `config.yaml`，修改后免重启即刻生效。
- **视觉体系**：以 Go 品牌蓝 (`#00ADD8`) 与 Koishi 品牌紫 (`#9580ff`) 为主基调；支持“跟随系统 / 浅色 / 深色”三态循环切换。
- **安全密码机制**：默认密码为 `storeluna-gogo`；若未修改，控制台启动输出显式警告框，且 WebUI 顶栏常驻黄色高危风险提示。

## 5. 部署与 CI/CD 矩阵
- **Docker 部署示范 (84 机器宿主机局域网绑定)**：
  ```bash
  docker run -d \
    --name storeluna-gogo \
    --restart unless-stopped \
    -p 55150:55150 \
    -p 192.168.31.84:65150:65150 \
    -v /home/bawuyinguo/SSoftwareFiles/koishi/storeluna-gogo/config.yaml:/app/config.yaml \
    -v /home/bawuyinguo/SSoftwareFiles/koishi/storeluna-gogo/data:/app/data \
    vincentzyu233/storeluna-gogo:latest
  ```
- **CI/CD 构建矩阵**：
  - **GitHub Release**：静态编译产出 `linux/amd64`, `linux/arm64`, `windows/amd64`, `windows/arm64`。
  - **Docker Hub**：基于 GitHub Actions 构建多架构镜像 (`linux/amd64`, `linux/arm64`) 推送至 `vincentzyu233/storeluna-gogo`。
